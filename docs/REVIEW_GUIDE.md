# 项目实现说明

本展示包从AI 内容创作系统与 AI 内容工作流两个项目中选取部分实现。以下说明这些代码在原项目中的用途、处理方式及本包可运行的范围。

## V2｜内容市场研究模块

这里展示 AI 内容创作系统（V2）的内容市场研究模块。该模块将内容样本的采集、筛选、分类和统计集中到 Web 工作台，为选题研究提供资料。本包选取 TikHub 小红书搜索入口及相关处理代码；完整研究报告和后续内容生产衔接未收录。

### 数据接入与保存

工作台生成搜索参数，通过应用自身的代理接口请求第三方服务。响应返回浏览器后，先规范化字段，再经过原项目的补详情与规则初筛、候选合并和保存队列，最后由内部数据库接口写入 MySQL。补详情、完整规则初筛和保存队列未收录；本包保留请求、规范化、合并及数据库存取的选定实现。

`normalizeSearchResults` 处理字段别名、字符串数值和标题，`extractSearchPagination` 提取分页信息；`mergeCandidates` 按内容身份合并记录，保留已有正文和分类。未返回的指标保留为空，真实零值保留为零。如果把缺失值补成零，就会把“尚未获取数据”误当成“没有互动”，影响样本比较和统计解释。

付费请求发送前，`claimPaidRequest` 核对已登记的调用尝试、参数签名、执行锁和预算。成功响应可复用缓存；请求超时或响应落库失败时，记录待核账状态。原因是请求失败不一定代表服务商未处理或未计费，直接重试可能重复付费，因此先核账再决定是否重发。

保存端的 `saveAuthoritativeState` 在 MySQL 事务中锁定当前状态，按调用方式核对业务版本，再更新状态与候选，失败时回滚。浏览器读取可重试暂时性错误，保存请求不自动重放。请求、锁和事务部分为静态代码选摘，离线测试只运行其中的预算与参数检查函数。

### 模型复核与统计

规则初筛在保存前给出初步分类，模型复核是保存后的后台任务。保存成功但模型任务未启动时，浏览器收到提醒，已保存数据仍然保留；这将模型故障与采集保存分开处理，避免仅因模型不可用就重新采集已有样本。

模型复核在后台调用 `CodexAppServer.classify`，通过回执记录请求状态；已完成结果可复用，失败或结果不明时停止自动重试。

`validateReviews` 检查返回数量、样本身份、重复 ID、分类和信号字段的允许取值。后台写回前还会比较输入内容的哈希，防止旧输入的结果覆盖已修改的样本。这些检查控制返回结构和版本，不判断分类结论是否正确。

页面使用工作台状态进行聚合。离线演示选取数量、占比和互动中位数三个统计项：小红书互动量合计已知的点赞、收藏和评论，全部缺失时为空；每个分类内按内容身份去重，占比以各分类去重数量之和为分母。页面组件保留在静态片段中，不是可启动页面，也未直接调用本包的离线演示入口。

`examples` 中同一批 5 条演示响应展示输入与输出。例如点赞 10、收藏 3、评论 2，互动量为 15。分类来自预设测试值，没有执行模型推理。

## V3｜AI 内容工作流

原项目按素材、母稿、终稿、文字组合和平台包推进。Skill 组织工作，人工审阅内容，Python 阶段检查脚本（下文称“门禁”）核对确认记录与文件版本。保留人工确认，是因为格式正确、文件齐全并不代表材料能支持结论，也不代表内容已经获准发布；这些判断不能由状态检查代替。

### 阶段衔接

素材确认和关键素材读取记录齐全后，才能进入初稿；母稿确认、质量依据和当前指纹有效后，才能整理终稿；终稿与母稿的版本关联匹配后，才能准备标题、开头和收尾组成的文字组合；该组合确认后，才进入平台制包。

本包保留上述门禁和测试，并用两个精简展示 Skill 说明写作与制包的分工。示例素材、初稿、终稿使用合成数据及预设确认状态，截止于制包前的门禁检查，没有生成实际公众号包。

### 内容变更后的处理

`check_stage_gate.py` 同时检查状态字段、文件唯一性和内容指纹。例如终稿修改后，即使旧确认仍写着“已确认”，版本检查也会阻断制包；标题或收尾变化后，同样需要对应当前内容重新核对。

脚本检查记录，不能认证审批人或判断事实与表达质量；素材包内容也未通过哈希绑定母稿，素材后改仍需人工复核。平台部分只收录本地图片引用解析函数，不检查文件是否存在、图片尺寸或视觉效果。

## 离线运行示例

记录时间：2026-10-17；环境：Node.js v24.15.0、Python 3.14.3。以下为实际执行结果，输入使用合成数据和预设状态，未调用外部 API、模型或数据库。

### V2：整理输入与拒绝异常返回

在 V2 目录运行 `node examples/offline-demo.mjs`，得到 5 条规范化样本。第一条样本的点赞、收藏、评论分别为 10、3、2，互动量为 15。聚合结果节选如下：

| 预设分类 | 样本数 | 占比 | 互动中位数 |
| --- | --- | --- | --- |
| 教程／实践 | 3 | 60% | 30 |
| 工具／产品测评 | 2 | 40% | 0 |

异常演示向 `validateReviews` 提交两个样本的预设返回，将两个返回项的 ID 都设为第一个样本的 ID。函数抛出以下异常，调用方捕获并打印消息：

```text
AI 返回非法分类或重复身份，未写入
```

这次只执行校验函数，没有数据库写入。“未写入”是函数的错误消息，不代表执行过数据库回滚。同类重复身份场景已在 `tests/offline.test.mjs` 中覆盖，可用 `node --test tests/offline.test.mjs` 复核。

### V3：原版本通过，终稿变化后阻断

在 V3 目录运行：

```powershell
python -B scripts/check_stage_gate.py --article-dir examples/synthetic-case --next platform-package
```

正常示例退出码为 `0`，输出首行：

```text
门禁通过：可以进入 platform-package
```

随后将示例复制到临时目录，仅在终稿末尾追加一行，保持旧指纹不变；同一命令改为检查临时目录，退出码为 `2`：

```text
门禁未通过：终稿文件已变；先核对当前终稿，再记录关联
```

原演示文件未改动。该结果验证版本变化能被识别，不代表测试稿已经获得实际发布授权。
